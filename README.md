# 手代（banto-plugin-tedai）

[Banto](https://github.com/bantojs/banto) の外部プラグインです。注文のお知らせ（受付・発送など）のメールを Banto の代わりに送り、会員の購入に応じて、決めておいたアプローチ（LINE・メール・クーポン・会員の項目）と、お店の作業（注文に印・運営者への知らせ）を自動で行います。

> **無保証です。** MIT ライセンスで、現状のまま提供します（[LICENSE](LICENSE)）。開発チームはこのプラグインを置いた Worker のホスティング・稼働・データに責任を持ちません。**テレメトリは送りません**（開発チームへの通信はありません。wrangler の利用状況の送信も `wrangler.jsonc` で止めています）。

- 必要な Banto: **v0.10.0 以上**（「つなぐ」0088、外部プラグイン向けの口 0105、注文の印 0106）。お気に入りを写すのは 0123 から。注文のお知らせは **0172・0173 から**（「メール通知」の注文のメールを止める設定・注文の追跡番号・`orders:contact`）。お店で試着のお知らせも **0172・0173 から**（「メール通知」の試着のお客様あてを止める設定）。期限の前日・延長の知らせは 0151・0152 から。「LINE だけ」のお客様を見分けるのは 0176 から。お支払いのお願いは **0182 から**
- 動かす場所: 運営者自身の Cloudflare アカウント（Workers + D1）。1 つの Banto に 1 つの手代を置き、ショップごとにつなぎます
- Banto 本体のコードは読み込みません。Banto の公開の契約（[hooks](https://github.com/bantojs/banto/blob/main/docs/hooks.md)・[つなぐ](https://github.com/bantojs/banto/blob/main/docs/hooks.md#6-つなぐ0088)・[AI 用 API](https://github.com/bantojs/banto/blob/main/docs/ai-access.md)）だけで動きます

## できること

| | 中身 |
| --- | --- |
| 注文のお知らせ | ご注文の受付・入金の確認・発送・キャンセルのメールを、会員にもゲストにも送る（文字だけか飾りあり、明細つき） |
| お店で試着のお知らせ | お申し込みの受付・ご用意（取り置き）・期限の前日・延長・取り消しのメールを、お客様に送る（品目と店舗の住所・営業時間つき） |
| お支払いのお願い | KOMOJU（コンビニ払い・銀行振込など）で 24 時間たっても払われていないお申し込みに、お支払いに進むリンクつきのメールを 1 回送る |
| きっかけ | 会員の注文が支払われた・最後の購入から n 日（休眠）・初めての購入から n 日・お気に入りの商品の再入荷 / 値下げ / 残りわずか・カゴ落ち |
| 条件 | 決めた商品の集まりを 1 回の注文で全部買った・n 種類以上買った・合計 n 点以上買った、注文の回数、累計の購入額（それぞれ直近の日数かいつでも） |
| アクション | 会員の項目を書く、注文に印を付ける、クーポンを配る、お客様に連絡する（LINE / メール / LINE、届かなければメール）、運営者に知らせる（Slack・メール） |
| 回数と時間 | 同じ会員に同じルールは 1 回、n 日後に行う（行う直前に確かめ直す）、お客様ごとの上限、夜は送らない |
| 試す・調べる | 試しに当てる（人数と文の見本）、記録だけ（送らない）で動かす、送った記録、会員で確かめる（当たらない理由） |

ルールの対象は **会員だけ** です（ゲストの注文は同じ人の注文としてまとめられないため）。注文のお知らせは会員にもゲストにも送ります。

## 注文のお知らせ

Banto の同梱プラグイン「メール通知」が送っている注文のメールを、手代が引き受けます（管理画面の「注文のお知らせ」）。

| 種類 | 送るとき | 必ず入れる差し込み |
| --- | --- | --- |
| ご注文の受付 | お支払いが済んだとき（`order.paid`）。代金引換などの未入金の注文は、注文を確定したとき（`order.created`） | `{{order_details}}` |
| 入金の確認 | 未入金の注文に、運営者が入金を記録したとき（`order.paid` の入金の記録） | なし |
| 発送 | 「発送済み」にしたとき（`order.shipped`） | `{{order_details}}`・`{{tracking}}` |
| キャンセル | 「キャンセル」にしたとき（`order.cancelled`） | なし |

- 差し込みは `{{name}}`（注文のお名前、無ければ「お客様」）・`{{shop}}`・`{{order_number}}`・`{{order_total}}`・`{{order_url}}`・`{{payment_method}}`・`{{contact}}`（設定の問い合わせ先）と、明細の `{{order_details}}`（1 行に単独で。飾りありでは表になります）・発送のお問い合わせ番号の `{{tracking}}`（1 行に単独で）。
- `{{order_url}}` は Banto の注文照会のページです（`?banto_order=<番号>`、会員の注文は `&banto_member=1`。秘密は載せません）。ゲストは注文番号が入った状態で開き、メールアドレスを入れて確かめます。連携サイトに注文照会のページを向けていれば、Banto がそこへ移します。
- `{{tracking}}` は発送のお問い合わせ番号です（1 行に単独で。運送会社・番号・追跡のリンク。Banto 0172 の注文の `tracking`）。番号の無い注文では、ご注文の確認ページを案内します。
- 宣伝ではないので、案内メールの同意が無いお客様にも送り、お客様ごとの上限・夜は送らない時間・配信停止のリンクは使いません。**文面に宣伝を入れないでください**（入れると特定電子メール法の広告メールになります。宣伝は「ルール」で）。
- 宛先とお名前は送る直前に Banto から読み（`orders:contact`。住所と社内のメモは読みません）、D1 には置きません。送った記録に置くのは注文 ID・番号・種類・時刻と結果だけで、90 日で消します。
- 文面の画面の「試しに送る」で、いま画面にある文面（保存はしません）を見本の注文で作り、「設定」の運営者への知らせの宛先に 1 通送れます（件名の頭に [試し送り]、お客様には送りません。30 秒に 1 通まで）。
- お客様が Banto の会員ページで「お知らせを LINE だけで受け取る」を選び、Banto がそれを効かせた知らせ（Banto 0176、hooks の `notice_line_only`）は、メールを送りません（お店で試着も同じ）。Banto が LINE で送ります。送った記録には「LINE だけ」と残ります。LINE で届けられなかったとき、Banto は手代へ配り直さないので、そのお客様にはメールも届きません（Banto の docs/line.md §2）。
- 出来事を受け取った直後に送り（SMTP のときは Cron で 5 分以内に）、送れなければ 5・10・20・40 分後にやり直します（5 回で失敗）。同じ注文の同じ種類は 1 回だけです。
- 宛先やメールの中身への断り（存在しない宛先など）はやり直さずに失敗にします。送り手の設定の誤り（Resend のキー・送り元のドメインの確認、SMTP の認証）はやり直しを続けるので、そのあいだに直してください。失敗した知らせ（7 日以内に受け取ったもの）は、画面からまとめて送り直せます。

### 切り替えの手順

1. Banto を **0172・0173 の入った版**に上げる
2. Banto の管理画面 → プラグイン → 同梱の「メール通知」で、**「注文のメールを送らない（外部プラグインに任せる）」に印を付ける**（付けないとお客様に 2 通届きます）。「メール通知」自体は **OFF にしない**でください（会員のログインのコード・招待・お問い合わせなどのメールの送信元です）。この印で Banto からの**運営者への注文の控えも止まる**ので、新しい注文を知りたいときは同梱の「LINE 通知」を ON にします
3. 手代を **つなぎ直す**（`orders:contact` を許すため。Banto はつないだ後に権限を広げません。前の版の手代で `orders:pii` を許してつないだショップは、つなぎ直さなくても動きます）。Banto の管理画面 → 連携 → 手代 の購読する出来事に、`order.created`・`order.shipped` があることを確かめる
4. 手代の「注文のお知らせ」で、種類ごとに文面を整えて「手代が送る」にする（メールの送り手・送り手のアドレス・`orders:contact` がそろうまでは選べません）。「試しに送る」で見た目を確かめます

## お店で試着のお知らせ

Banto の同梱モジュール「お店で試着」のお客様あてのメールを、Banto の「メール通知」の代わりに手代が送ります（管理画面の「注文のお知らせ」の下の「お店で試着」）。店舗あてのお知らせ（申し込みがありました・延長がありました）と LINE は、今までどおり Banto が送ります（店舗のアドレスは手代に渡りません）。

| 種類 | 送るとき | 必ず入れる差し込み |
| --- | --- | --- |
| 試着のお申し込みの受付 | お客様が申し込んだとき（`tryon.requested`） | `{{tryon_items}}`・`{{store_info}}` |
| ご試着いただけます | 店舗で「取り置き中」にしたとき（`tryon.updated` の ready） | `{{hold_until}}`・`{{tryon_items}}`・`{{store_info}}` |
| お取り置きの期限の前日 | 期限の前日（Banto の試着の設定で時刻を決めたとき。`tryon.updated` の reminder） | 同上 |
| お取り置きの延長 | お客様が会員ページで延長したとき（延長のたびに 1 通。`tryon.updated` の extended） | 同上 |
| 試着のお申し込みの取り消し | 取り消したとき（`tryon.updated` の cancelled） | `{{tryon_number}}` |

- 差し込みは `{{name}}`（申し込みのお名前）・`{{shop}}`・`{{tryon_number}}`（受付番号）・`{{store_name}}`・`{{hold_until}}`（取り置きの期限、例「12月8日（火）」）・`{{visit}}`（来店予定日の行。受付だけ）・`{{contact}}`・`{{shop_url}}`（お店のトップ。ボタンやリンクの先に使えます）と、品目の `{{tryon_items}}`・店舗の案内の `{{store_info}}`（どちらも 1 行に単独で）。差し込みと必ず入れるものは、Banto の「お知らせの文面」の試着の決まりにそろえています。
- 店舗の案内は、店舗の名前・住所・電話・曜日ごとの営業時間・45 日先までの臨時休業 / 臨時営業です。店舗を読む権限（`shop:read`）の無いつなぎ方では、店舗の名前だけになります。
- 宛先とお名前は送る直前に Banto から読み（`orders:contact`）、D1 には置きません。送った記録に置くのは申し込みの ID・受付番号・種類・時刻と結果だけです。
- 積んだ後に申し込みの状態が変わったら（取り置きの前に取り消した など）、古い知らせは送りません（「送る前にお申し込みの状態が変わった」）。
- 注文のお知らせと同じく宣伝ではないメールとして送ります。文面に宣伝を入れないでください。

### 切り替えの手順（お店で試着）

1. 手代を **つなぎ直す**（`shop:read` と、出来事 `tryon.requested`・`tryon.updated` を許すため。この版より前からつないでいるショップ）。Banto の管理画面 → 連携 → 手代 の購読する出来事に、`tryon.requested`・`tryon.updated` があることを確かめる
2. 手代の「注文のお知らせ」→ お店で試着 で、種類ごとに文面を整えて「手代が送る」にする。「試しに送る」は見本の申し込みで作ります
3. Banto の管理画面 → プラグイン → 同梱の「メール通知」で、**「お店で試着のお客様あてのお知らせを送らない」に印を付ける**（付けないとお客様に 2 通届きます）

## お支払いのお願い（KOMOJU）

KOMOJU（コンビニ払い・銀行振込など）でお申し込みのあと、24 時間たってもお支払いが確認できないお客様に、Banto が 1 回だけ出す知らせ（hooks の `checkout.payment_pending`、Banto 0181）を受けて、手代がメールを送ります（管理画面の「注文のお知らせ」の下の「お支払いのお願い（KOMOJU）」）。Banto の「メール通知」で「注文のメールを送らない（外部プラグインに任せる）」に印を付けたショップは、Banto からはお支払いのお願いのメールが出ないので、手代が送ります。

- 必要な Banto: **0182 の入った版**（予約の中身を読む口 `GET /api/v1/reservations/{id}/payment-reminder`）。当たっていなければ「Banto が古い」で失敗にします。
- Banto の管理画面 → ショップの設定 → お知らせの文面 で **「お支払いのお願いを送る」を ON** にします。OFF のあいだは Banto が知らせを出さないので、手代も送りません。
- 差し込みは `{{name}}`・`{{shop}}`・`{{total}}`（お支払い金額）・`{{pay_until}}`（お支払いの期限、Banto の運営者の時間帯で「11月28日（土）15:00」）・`{{payment_method}}`（コンビニ払い など）・`{{payment_link}}`（必須）・`{{contact}}` と、品目と合計の `{{items}}`（1 行に単独で）。
- `{{payment_link}}` は、お支払いに進む・お申し込みを取りやめる画面のリンクです（Banto が予約ごとに署名した券つき、お支払いの期限まで）。ボタンの先（`[[お支払いに進む]]({{payment_link}})`）にも使えます。リンクは宛先と同じく `orders:contact` を許したつなぎ方にだけ Banto が渡します（開くとお申し込みを取りやめられるため）。D1 には置きません。
- 送る直前に Banto に予約を聞き直し、もう払った・取りやめた・期限が切れたお申し込みには送りません。Banto がリンクを組めないとき（Banto の `PUBLIC_BASE_URL` もショップのドメインも無い）は送らずに失敗にします。
- 「LINE だけ」を選んだお客様には送りません（Banto が LINE で送ります）。
- 宣伝ではない取引の知らせとして送ります。文面に宣伝を入れないでください。

## ルール

管理画面（Banto の連携 → 手代）で作ります。

1. **きっかけ**:
   - 会員の注文が支払われたとき（その注文でちょうど条件に入った会員）
   - 最後の購入から n 日たったとき（そのあいだ買っていない）・初めての購入から n 日たったとき。5 分ごとに、ルールが動いているあいだにちょうど n 日を過ぎた会員を探します。休眠のルールは、待っているあいだに買ったら行いません
   - お気に入りの商品が再入荷した（見る単位の在庫がゼロからありに。商品ごとなら、サイズ・色の 1 つだけが戻っても、ほかの SKU に在庫があるあいだは当たりません）・値下げした（いちばん安い SKU の値段が下がった）・残りわずかになった（Banto の在庫僅少の知らせ）とき。その商品をお気に入りに入れている会員に、会員 × 商品で 1 回。「その商品をもう買った会員は除く」を選べます。行う直前に、まだお気に入りか・（再入荷と残りわずかは）在庫があるかを Banto で確かめます。文に `{{product_name}}`・`{{product_url}}` を差し込めます
   - お気に入りのきっかけは **見る単位** を選べます（Banto の SKU のオプションと同じ考え方）: 商品ごと（既定。商品の在庫の合計・最安値）／オプションを選ぶ（例: カラーを選ぶと「赤のどれか」がゼロからありに戻ったら当たる）／SKU ごと（全部のオプションの組み合わせ）。当たりは会員 × 商品 × そのまとまりで 1 回、文に `{{variant}}`（例「カラー: 赤」）を差し込めます。お客様がどのサイズ・色を待っているかは分からないので、ふだんは商品ごとがおすすめです
   - カゴ落ちしたとき（会員がレジまで進み、払わずに期限が切れた。Banto の `checkout.abandoned`。ゲストは Banto が送らない）。会員 × カゴで 1 回。期限切れのあとに決済が済むことがあるので、**少なくとも 1 時間待ってから、レジを始めたあとに買っていなければ** 行います。文の `{{product_name}}`・`{{product_url}}` はカゴの最初の商品です
   - 注文以外のきっかけは、購入の条件が無くてもかまいません
2. **商品の集まり**: ルールに使う商品のまとまり（200 商品まで）。名前で探して足すか、カテゴリー（下のカテゴリーも）の商品をまとめて足します。SKU ではなく商品で数えます（カラー違いは同じ商品）。
3. **条件**: 次の部品を組み合わせ、すべて満たしたら当たります。
   - 商品の集まりを買った: 1 回の注文で全部 / n 種類以上 / 合計 n 点以上
   - 注文の回数: n 回以上
   - 累計の購入額: n 円以上（値引き後・送料込み）
4. **試しに当てる**: 保存の前に、今この条件に当たる会員の数と見本（名前とメールの一部。画面を開いたときに Banto から読む）、文の見本を出します。
5. **アクション**（状態が「動かす」のとき、上から順に。5 分ごとの Cron で行い、失敗は 5・10・20・40 分後にやり直す）:
   - 会員の項目を書く（Banto の「会員の項目」に定義したキー。会員の条件・会員価格・限定商品につながる）
   - きっかけの注文に印を付ける
   - クーポンを配る（会員 1 人に 1 枚。文に `{{coupon_code}}` で差し込める）
   - お客様に連絡する: LINE（Banto がショップの公式アカウントから送る）/ メール / LINE、届かなければメール。差し込みは `{{name}}`・`{{shop}}`・`{{coupon_code}}`。メールは「文字だけ」か「飾りあり（HTML）」（下の「飾りのあるメール」）
   - 運営者に知らせる（Slack・メール。載せるのはルールの名前・会員 ID・注文 ID・結果だけ）
6. **待ち**: 当たってから n 日後（90 日まで）に行えます。待ったあと、行う直前に条件を確かめ直し、キャンセル・期間切れなら行いません。
7. **お客様への連絡の歯止め**（設定）: 全ルールを合わせたお客様ごとの上限（既定 1 日 1 通・7 日 3 通）と、夜は送らない時間（既定 21 時〜9 時、日本時間）。超える・夜の連絡は後ろへずらし、7 日たっても上限が空かなければ連絡だけ飛ばします。
8. **状態**: 下書き / 記録だけ（当たった会員を記録する。送らない）/ 動かす / 止めている。記録だけ・動かすのルールは合わせて 20 個まで。
9. **送った記録**: 全ルールまとめて（目次の「送った記録」）とルールごとに、会員・状態・連絡の結果（LINE / メール / 送らなかった理由）。
10. **会員で確かめる**: 会員 ID を入れると、条件の部品ごとの今の値と、当たる・当たらない理由を出します。

**当たるのは「ちょうど条件に入った会員」だけ**で、同じ会員に同じルールは 1 回です（お気に入りのきっかけは会員 × 商品で 1 回）。ルールを動かし始める前にもう条件を満たしていた会員には当たりません（試し直すときは新しいルールを作ります）。つないだ直後に取り込む過去の注文でも当たりません。

## 置き方

### 1. Worker を置く（どれか 1 つ）

**A. Deploy ボタン**

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/bantojs/banto-plugin-tedai)

**B. Git から（Cloudflare の Workers Builds）**

Cloudflare の画面 → Workers & Pages → 作成 → GitHub のリポジトリ（このリポジトリを fork したもの）。ビルドのコマンドは空、デプロイのコマンドは `npx wrangler deploy`、ルートのディレクトリは空のまま。

- Cloudflare の GitHub App に、そのリポジトリへのアクセスを許しておく（無いと自動デプロイが動きません）
- **本番のブランチ（Production branch）を `main` にします**（Worker の設定 → ビルド → ブランチの設定）。違うブランチのままだと、`main` にマージしてもプレビューの版ができるだけで本番にはデプロイされず、ビルドの結果も失敗と出ることがあります
- ビルドのブランチを変えたあとの「Retry build」は、前のコミットをもう一度ビルドします。新しいブランチで動かすには、そのブランチに push します（画面から最新のコミットをビルドする手段は無いので、次の変更を入れたときに本番に出ます）
- 「Could not detect a directory containing static files」と出たら、ビルドしているブランチに `wrangler.jsonc` がありません（ブランチかルートのディレクトリの違い）

**C. コマンドで（開発者向け）**

```bash
git clone https://github.com/bantojs/banto-plugin-tedai.git
cd banto-plugin-tedai
npm install
npx wrangler secret put TEDAI_SECRET
npx wrangler deploy --var BANTO_URL:https://<Banto の URL>
```

どれでも、D1 のデータベースは最初のデプロイで作られ、表は Worker が最初の要求で作ります（マイグレーションのコマンドは要りません）。

### 2. 値を入れる

Cloudflare の画面 → Workers & Pages → 手代の Worker → 設定 → **変数とシークレット**:

| 名前 | 種類 | 値 |
| --- | --- | --- |
| `BANTO_URL` | 変数 | Banto 自身の URL。**Banto の `PUBLIC_BASE_URL`**（設定していなければ、管理画面を開く URL）と同じにします。ショップの独自ドメイン（お店の画面のドメイン）は使えません（Banto はそこで AI 用 API と管理画面を出さないため）。手代はこの Banto とだけつなぎます |
| `TEDAI_SECRET` | **シークレット** | 32 文字以上の乱数（`openssl rand -hex 32` など）。**変えると、つなぎ直しが要ります**。送り済みの案内メールの配信停止のリンクも使えなくなるので（お客様が止められなくなる）、漏れたとき以外は変えないでください |
| `WORKERS_PLAN` | 変数（任意） | Cloudflare の Workers のプラン。`free`（既定）か `paid`。有料プランにしたら `paid` にします（下の「Workers のプラン」） |

メールと Slack を使うときは、「メール」の節の値も入れます。

`https://<手代の Worker>/` を開いて「受け口の URL に次を入れて…」と出れば、値は通っています。

### 3. Banto とつなぐ

1. Banto の管理画面 → **連携** → 送信先を追加 で、受け口の URL に `https://<手代の Worker>/` を入れる
2. 求める権限が出るので、確かめて「許してつなぐ」を押す。手代の画面に「つなぎました」と出れば済みです（秘密を手で写す必要はありません）
3. 「つなぎました」の画面に出る **持ち主のコード**（24 時間・1 回限り）を控え、連携の画面から手代の画面を開いて入れてください。コードを入れた人が、手代の画面の持ち主になります。連携の画面の「テスト送信」が 200 なら、Banto からの知らせも届いています

- 「許してつなぐ」を押す人には、そのショップの権限の項目 **注文（orders）・商品（catalog）・会員（customers）・集客（marketing）** が要ります（組織の owner / admin なら持っています）
- **手代の画面を使える人**: 手代はつないだ人の権限で Banto を読み書きします（会員の名前・クーポン・LINE・メール）。Banto は手代の画面を、ショップの「連携」の項目を持つ人なら誰にでも開かせるので、手代の側で、使えるのを持ち主（つないだときの持ち主のコードを入れた人）と、持ち主が許した人だけにしています。ほかの人が開くと「許しがありません」と出て、持ち主の「設定」→「この画面を使える人」に並ぶので、持ち主が「許す」を押します。**つなぎ直しても持ち主は変わりません**（Banto では「連携」の項目があればだれでもつなぎ直せるため）。持ち主を替えるときは、持ち主が許した人に「持ち主を移す」を押します。**0.4.0 より前からつないでいるショップは、上げたあと一度つなぎ直してください**（持ち主がまだいないので、つなぎ直すと持ち主のコードが出ます。それまではだれも画面を使えません）
- **持ち主と許した人の違い**: メールの送り手のアドレス・返信先・運営者への知らせの宛先（だれに・どのアドレスから送るか）を変えられるのは持ち主だけです。ルール・文面・注文のお知らせの設定は、許した人も変えられます
- **持ち主のコードを入れるまで**: つないでから（0.4.0 に上げてから）持ち主のコードを入れるまでは、ショップの「連携」の項目を持つ人がつなぎ直すと、その人に新しいコードが出ます。つないだらすぐにコードを入れてください。また、つなぎ直すと手代はつなぎ直した人の権限で動きます（Banto の監査ログの「誰が」もその人になります）。権限の狭い人がつなぎ直すと、使えない機能が出ます
- **持ち主がいなくなったとき**（退職などで「持ち主を移す」を押せない）: 手代の Worker を置いた Cloudflare のアカウントの人が、手代の D1 で `DELETE FROM admin_users WHERE shop_id = '<ショップの ID>';` を実行してから、つなぎ直してください（新しいコードが出ます）。Cloudflare の画面の D1 → `banto-plugin-tedai` → コンソールか、`npx wrangler d1 execute banto-plugin-tedai --remote --command "…"` で行えます
- 手代の Worker の URL（ホスト）を変えたら、Banto の連携の画面でつなぎ直してください（つないだ連携は、ホストの違う URL に書き換えられません）。Banto の URL を変えたときは、`BANTO_URL` を書き換えます
- 同じ Cloudflare アカウントに Banto と手代を置くときも、そのまま届きます（`wrangler.jsonc` の `global_fetch_strictly_public`）

### 4. Banto 側で用意するもの（使うアクションだけ）

| アクション | Banto で |
| --- | --- |
| クーポンを配る | モジュール「クーポン」を ON にして、配るクーポンを作る |
| 会員の項目を書く | ショップ設定 → 会員の項目 でキーを定義する |
| メール | ショップ設定で「案内メールの同意」の欄を出す（同意した会員にだけ送るため） |
| LINE | LINE 公式アカウントをつなぎ、宣伝の月の上限（`line_marketing_limit`）を決める（Banto の docs/line.md） |

### 受け取る出来事

`order.created`・`order.paid`・`order.shipped`・`order.cancelled`・`customer.deleted`・`favorite.added`・`favorite.removed`・`product.updated`・`inventory.low`・`checkout.abandoned`・`tryon.requested`・`tryon.updated`・`checkout.payment_pending`。
`order.created`・`order.shipped` は注文のお知らせだけが、`tryon.requested`・`tryon.updated` はお店で試着のお知らせだけが、`checkout.payment_pending` はお支払いのお願いだけが使います。送る種類が無いショップでは、受け取るだけで何もしません（D1 にも書きません）。
**Banto は受け取る出来事を、つないだときに決めて覚えます**（マニフェストを取り直しても変わりません）。手代を上げて出来事が増えたとき（0.2 で `order.created`・`order.shipped`・`checkout.abandoned` を足した）は、Banto の管理画面 → 連携 → 手代 で受け取る出来事を選び直して保存してください。手代のルールの画面に、カゴ落ちを最後に受け取った時刻が出ます。

`product.updated`・`inventory.low` はお気に入りの商品のきっかけに使います。お気に入りのルールが動いていないショップでは、受け取るだけで何もしません（D1 にも書きません）。

## Workers のプラン

手代は 5 分ごとの Cron で、アクション・時刻のきっかけ・注文とお気に入りの突き合わせを行います。Cloudflare の Workers は 1 回の呼び出しで使える数に上限があり、越えるとその回の残りの仕事がすべて失敗します。

| | 無料プラン | 有料プラン |
| --- | --- | --- |
| D1 の問い合わせ | 50 | 1,000 |
| 外への通信（**D1 の呼び出しも含む**） | 50 | 10,000 |

- 手代は Cron の中で D1 と外への通信を数え、**上限の手前で止めて、残りを次の回に回します**。仕事は 1 件ごとに見積もりが収まるかを見てから始め、仕事の順番は回ごとに回し、ショップとルールは前に見た時刻の古い順に見るので、毎回同じ仕事が後回しになることはありません。
- **3 回（15 分）続けて止めたら**、手代のホームに「5 分ごとの仕事が上限に近いため続けて途中で止まっています」と、日時と止めた仕事を出します（直近 7 日）。たまに次の回へ回すだけなら出しません。
- **無料プランで扱えるのは、つなぐショップ 2 つまでが目安**です（ルール・注文・お気に入りの無い状態で、1 回にショップ 1 つで 24 回・2 つで 40 回使い、3 つでは上限の手前で毎回止まります。ルールや連絡が多いともっと少なくなります）。ホームにこの知らせが出るようになったら、Cloudflare の **Workers の有料プラン**にして、手代の Worker の変数 `WORKERS_PLAN` を `paid` にしてください。
- 有料プランにしても `WORKERS_PLAN` を変えないままだと、手代は無料プランの数で止め続けます。
- Cloudflare の無料プランの Cron のトリガーは、アカウント全体で 5 つまでです（Banto も 1 つ使います）。ショップごとに手代を分けて置くときは、この数にも気をつけてください。

## メール（任意）

宣伝のメールは **案内メールに同意した会員だけ** に送ります（Banto の `marketing_consent`。送る直前に Banto で確かめます）。

送り手は手代の持ち物です（Banto のログイン・注文のメールとは別。そちらの評判を守るため）。Worker の変数で 1 つ選びます。

| 名前 | 種類 | 値 |
| --- | --- | --- |
| `MAIL_TRANSPORT` | 変数 | `resend` か `smtp` |
| `RESEND_API_KEY` | シークレット | Resend の API キー（`resend` のとき）。送るだけの権限で、送り元のドメインに絞ったキーがおすすめ |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_TLS` | 変数 | SMTP のサーバー（`smtp` のとき）。25 番は Cloudflare が塞いでいるので 587（`starttls`、既定）か 465（`on`）。暗号化しない `off` は受け付けません（お客様のアドレスと認証が平文で流れるため。0.4.0 より前に `off` にしていたら、上げるとメールを送れなくなるので `starttls` か `on` に変えてください）。1 通は 60 秒まで。本文を送った後に応答が来なかったもの・送っている途中で Worker が切れたものは「送れたかもしれない」と記録し、2 通届かないようにやり直しません（記録の画面で確かめてから送り直せます）。SMTP のときの注文のお知らせは、受け取りの直後ではなく Cron（5 分ごと）で送ります（受け取りの後に使える時間に、遅い SMTP の 1 通が収まらないことがあるため） |
| `MAIL_FROM_DOMAINS` | 変数（任意） | 送り手のアドレスに使ってよいドメイン（カンマ区切り、サブドメインも可）。`id:<ショップの ID>=ドメイン`（例 `id:1111…=shop-a.example`）か `slug:<URL の名前>=ドメイン` と書くとそのショップだけ（URL の名前は Banto で変えられ、手放した名前を別のショップが使えるので、`id:` を使ってください。`slug:` があると設定の画面に注意が出ます）、ドメインだけならどのショップでも使えます。1 つの手代に複数のショップをつなぐとき、あるショップが別のショップの送り元を名乗れないようにします（複数のショップをつないでいて `id:` の決まりが無いと、設定の画面に注意が出ます）。送り元の名前に `< > @` は使えません |
| `SMTP_USER` / `SMTP_PASS` | 変数 / シークレット | SMTP の認証 |
| `SLACK_WEBHOOK_URL` | シークレット | 運営者への知らせ（Slack の Incoming Webhook、任意）。1 つの手代につないだショップすべてで同じチャンネルに届きます |

- 手代の画面の「設定」の **試しに 1 通送る** で、運営者の宛先へ 1 通送って、送り手とアドレスを確かめられます（断られたら理由を出します）。
- 手代の画面の「設定」で、送り手のアドレスと **特定電子メール法の表示**（送信者の名前・住所・問い合わせ先）を入れます。そろうまでメールのアクションは使えません。メールの最後に、この表示と配信停止のリンクを手代が付けます。
- 送り手のアドレスは、送り手のサービス（Resend など）で確認済みのドメインのものにします。確認していないドメインだと断られ、送った記録が「失敗」になります。
- 宣伝のメールの評判を、ログイン・注文のメールと分けたいときは、送り元にサブドメイン（例 `news.example.com`）を使います。
- 配信停止のリンク（と、メールのアプリの「配信停止」ボタン用の `List-Unsubscribe`）を押すと、Banto に `marketing_consent: false` を書き戻します。
- 飾りのあるメール（HTML）: ルールのメールの形を「飾りあり」にすると、本文を下の書き方で書き、手代の決まったレイアウト（幅 600px、設定の **色** と **ロゴ**）に流し込みます。**生の HTML は書けません**（崩れ・差し込みの値の混入を防ぐため）。同じ本文から文字だけの版も作り、両方を入れて送ります（multipart/alternative）。特定電子メール法の表示と配信停止のリンクは、レイアウトの最後に手代が必ず付けます。ルールの画面の「試しに当てる」で見本が見られます。

  ```text
  # 見出し
  ## 小見出し
  段落は空行で分けます。**太字** や [リンク](https://…) も使えます。
  - 箇条書き
  ---
  ![画像の説明](https://…/image.jpg)
  [[ボタンの文字]](https://…)
  ```

  リンク・ボタン・画像は 1 通に 100 個までです。リンクとボタンの先は https:// の URL か、先まるごとの `{{product_url}}` です（書いた URL の中には差し込みを入れられません。お客様の値で飛び先が変わらないように）。画像は https:// の URL だけです。差し込みの値（お客様の名前など）はいつもエスケープし、飾りやリンクにはなりません。小見出しの `##` の後ろは全角の空白でも、箇条書きは `- ` のほか `・` でも書けます。太字の中にリンクも書けます（`**[セールのページ](https://…)**`）。
- SMTP には二重送信を防ぐ鍵が無いので、送っている途中で Worker が落ちたものは「送れたかもしれない」として送り直しません（2 通は届かない代わりに、まれに 1 通も届かないことがあります。送った記録で確かめてください。Resend は鍵で防ぐので送り直します）。

## データと個人情報

- 手代の D1 に置くのは、Banto の ID（会員・注文・商品）・数・金額・時刻・ルール・送った記録・お気に入り（会員 ID・商品 ID）だけです。**メールアドレス・氏名・住所は置きません**（送る直前に Banto から読み、使い終わったら捨てます）。LINE の利用者 ID とトークンは読むこともありません（LINE は Banto が送ります）。
- Banto から受け取ったトークンと署名シークレットは、`TEDAI_SECRET` から作った鍵で暗号化して D1 に置きます。
- 会員が退会したら（Banto の `customer.deleted`）、その会員の記録（購入・お気に入り・当たった記録・アクションの列）を消し、退会した会員の ID だけを残します（Banto は退会した会員の注文を残すので、読み直しや遅れて届いた hooks で記録を戻さないため）。0.4.0 より前に退会した会員は ID が残っていないので、Banto でその注文が更新されると記録が戻ることがあります。
- Cloudflare のログ（`observability`）には、要求の URL が残ります。手代の画面の作業の券（60 分）も URL に載るので、Cloudflare のアカウントのログを読める人を絞ってください。
- Banto で手代を外すと、手代は突き合わせで断られるようになり、6 時間に 1 回だけ試します（つなぎ直すと元に戻ります）。
- **Banto の連携の画面で手代を「外す」と**、手代には知らせが来ないので、手代は Banto にトークンを断られ始めた時刻を覚えます。**断られ続け、Banto からの知らせ（hooks）も届かないまま 30 日たつと、そのショップのお客様に関わる記録（購入・お気に入り・当たった記録・アクションの列・お知らせの記録）を消します**（Banto は権限が足りないときも断るので、知らせが届いているあいだは消しません。消すまでの日数は手代のホームに出ます）（ルール・文面・設定は残し、つなぎ直せば注文の写しは Banto から読み直します。消した後につなぎ直すと、前に当たった会員にもまた当たることがあります）。すぐに消したいとき・手代をやめるときは、Cloudflare の画面で手代の Worker と D1 のデータベース（`banto-plugin-tedai`）を消してください。

### プライバシーポリシーに書くこと（案）

手代を使うショップは、次のことをプライバシーポリシーに書いておいてください（文面はショップの状況に合わせて）。

- 購入の履歴（どの商品をいつ買ったか）とお気に入りを、お知らせ・クーポンの案内・会員の区分けに使うこと
- お知らせを LINE（ショップの公式アカウント）とメールで送ること。メールは同意した方だけで、いつでも止められること
- 注文のお知らせ（受付・発送など）を使う場合、ご注文のメールアドレス・お名前・注文の内容を、送るときに手代と送り手のサービスに渡すこと（手代は保存しません）
- お知らせの送信に、外部のサービス（使う送り手: Resend・SMTP のサーバーなど）を使うこと
- 運営者への知らせに Slack などを使う場合、会員 ID と注文 ID がそこに届くこと

文の中身（景品表示法など）・LINE 公式アカウントの規約は運営者の責任です。LINE の宣伝の通数は、Banto の月の上限（`line_marketing_limit`）と公式アカウントの料金プランの枠を使います。

## 購入の記録

- 会員の注文を、注文 × 商品で数えます。金額は値引き後です。キャンセル・返金された注文は数えません。
- 支払いの知らせ（hooks の `order.paid`）で記録し、5 分ごとに Banto の注文の一覧（更新の順）と突き合わせて、取りこぼしを拾います。`order.paid` の明細に商品 ID が載っていない Banto では、ルールはこの突き合わせのときに当たります（支払いから最大 10 分ほど）。
- つないだ直後は、同じ突き合わせで過去の注文を古い順に取り込みます（1 回に 540 件まで。1 万件なら 1.5 時間ほど）。

## お気に入り

- Banto のモジュール「会員のお気に入り」（0123）が ON のショップでは、会員のお気に入り（会員 ID・商品 ID・足した時刻）を写しておきます。お気に入りの商品の再入荷・値下げ・残りわずかのきっかけに使います。お気に入りに入っている商品だけ、前に見た在庫の合計と最安値を覚えます（覚える前の変化には当たりません。Cron で少しずつ読んでおきます）。
- つないだ直後に今あるお気に入りを取り込み、あとは hooks の `favorite.added` / `favorite.removed` と、5 分ごとの読み直しで追いかけます。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 手代の URL を開くと「まだ設定が足りません」 | `BANTO_URL`・`TEDAI_SECRET` の名前と値（`TEDAI_SECRET` は 32 文字以上） |
| つなぐときに「別の Banto とはつなぎません」 | `BANTO_URL` が Banto の `PUBLIC_BASE_URL` と違う |
| 手代の画面が「開き直してください」 | 画面の期限（60 分）が切れた。Banto の連携から開き直す |
| 手代の画面が空白（iframe に出ない） | Banto の管理画面を、`BANTO_URL` と違う URL で開いている |
| ルールに当たらない | ルールの画面の「会員で確かめる」に会員 ID を入れる（ルールを作る前に満たしていた・もう当たった・ゲストの注文、が多い） |
| 送った記録が「待ち」のまま | 理由の欄（夜・お客様ごとの上限・やり直し）。Banto のエラー（`banto 403 …` など）なら、トークンの権限かつないだ人の項目 |
| メールが届かない | 送った記録の結果（同意が無い・アドレスが無い）、送り手のサービスのログ、迷惑メールのフォルダ |
| Cloudflare の使用量で D1 の読み取りが多い | 手代の受け口（`/`）には、署名を確かめる前の要求もだれでも送れます。つないでいないショップの ID は 30 秒覚えて D1 を読まずに断りますが、気になるときは Cloudflare の WAF のレート制限（無料プランでも 1 つ作れます）を手代の URL の `POST /` にかけてください |
| ホームに「1 回の上限に近いため続けて途中で止まっています」 | ショップ・ルールが無料プランの上限に近い。Workers の有料プランにして `WORKERS_PLAN` を `paid` に（「Workers のプラン」） |

## 開発

```bash
npm install
npm run lint   # 型検査
npm test       # vitest（D1 の代わりに Node の組み込み SQLite）
npm run build  # wrangler deploy --dry-run
```

| ファイル | 役割 |
| --- | --- |
| `src/app.tsx` | 本体（Hono）。マニフェスト・hooks の受け口・つなぐ・配信停止。ランタイムに依存しない |
| `src/admin/` | 管理画面（サーバーで描く HTML。作業の券は Cookie でなくリンクとフォームで運ぶ） |
| `src/rules/` | 条件・アクションの形、当たる判定、会員で確かめる |
| `src/runs/execute.ts` | アクションの列を進める（Cron） |
| `src/budget.ts` | Cron 1 回の D1・fetch を数え、Workers の上限の手前で止める |
| `src/notices/` | 注文とお店で試着のお知らせ（種類・既定の文面・明細・品目と店舗の案内・送る列） |
| `src/mail/` | メールの送り手（Resend・SMTP。SMTP と MIME は Banto の実装を写したもの）と、飾りのあるメールの書き方・レイアウト（`html.ts`） |
| `src/store/` | 保存の層。SQL を流す継ぎ目（`sql.ts`）の上に表ごとの読み書き。D1 を直接呼ばない |
| `src/banto/` | Banto の口（引き換え・AI 用 API・署名の確かめ） |
| `src/index.ts` | Cloudflare Workers の入口（Cloudflare の型はここと `src/adapters/workers/` だけ） |
